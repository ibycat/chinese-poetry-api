01快速开始

无需注册、无需 Token，直接 GET。

# 山水 · 庐山
curl "BASE/shanshui/lushan.json"

# 抒情 · 爱情，纯文本
curl "BASE/shuqing/aiqing.txt"

# 植物 · 梅花，一次取 3 条
curl "BASE/zhiwu/meihua.json?n=3"

# 中文名直接访问
curl "BASE/抒情/爱情.json"

# 连续两句，全库随机（默认 JSON）
curl "BASE/line"

# 在指定多个分类中随机摘两句
curl "BASE/line.json?cats=t/songbie,t/jizeng"

# 多个分类随机摘句
curl "BASE/line.json?cats=t/songbie,t/jizeng,shanshui/lushan&n=3"

把 BASE 替换为上方地址即可。浏览器直接打开同样可用。

02路由规则

路径为 /{大类 slug}[/{小类 slug}]，省略小类时在该大类下随机。

路由说明
/all全部 {{TOTAL}} 首随机一首
/line全库随机返回连续两句；可加 ?cats= 合并多个分类
/{大类}如 /shanshui，在该大类全部诗词中随机
/{大类}/{小类}如 /shanshui/lushan
/t/{题材}按主旨取诗，如 /t/songbie、/t/bianzai，见第 03 节
/api分类总表 JSON（含每类的调用地址）
/doc本页
/browse/可视化分类浏览页（抽样数据）

注：今日诗词 v1 的 / 返回分类总表 JSON，本服务把 / 让给文档页，总表移到 /api， 其余路径完全兼容。

04参数与格式

格式说明
.json默认结构化返回，含全文与标签
.txt普通模式仅返回正文；摘句模式统一返回 JSON，.txt 后缀也被忽略
.svg图片，可直接 <img src>
参数说明
n返回条数，大于 1 时返回数组。全库 1–50；分类、题材、cats 最多 20
mode=line摘句模式：content 改为随机连续两句；可与任意分类路径组合
cats仅用于 /line：逗号分隔多个分类，如 t/songbie,t/jizeng,shanshui/lushan，最多 20 个

mode=line 不会改变分类、全文和标签。每首先按标点切成小句，再顺序两两成组； 长诗、长词因此有多个句对参与随机，不会永远只看开头两句。整首作品先被等概率选中， 再从句对中等概率取一联，长诗不会挤占短诗的出现机会。

cats 支持题材、大类、小类，slug 与中文名均可。多个分类先等概率选一个， 再在该分类内选作品和句对，因此不会因为某个分类语料更多而挤占其他分类。 例：/line.txt?cats=t/songbie,t/jizeng、 /line.json?cats=shanshui/lushan,zhiwu/meihua&n=5。

摘句统一返回 JSON，正文、句对位置和 poem 基本信息都在同一个对象中。 为了保证结构不丢失，摘句模式下即使 URL 写成 .txt 也返回 application/json； 普通分类的 .txt 仍只返回正文。

动态接口返回 Cache-Control: no-store，连续调用不会复用旧随机结果； /data/* 静态分片仍使用长缓存。

示例：直接嵌入网页

<div id="poem"></div>
<script>
fetch("BASE/shanshui/lushan.json")
  .then(r => r.json())
  .then(d => {
    document.getElementById("poem").textContent =
      d.content + " —— " + d.author + "《" + d.origin + "》";
  });
</script>

05返回结构

前四个字段与今日诗词 v1 完全一致，其后为扩展字段；v1 的解析器只读前四个，可直接替换。

{
  "content": "庐山小隐。",          // 首句；摘句模式下为连续两句
  "origin": "尾犯",               // 诗题 / 词牌
  "author": "晁补之",
  "category": "古诗文-山水-庐山",   // 命中的分类（多命中时随机取一）

  "mode": "line",                  // 仅摘句模式出现
  "title": "尾犯",                  // 诗题；与 origin 相同
  "lines": ["庐山小隐。", "..."],     // 组成该联的两句
  "line_index": 3,                    // 第几个句对（从 1 开始）
  "line_total": 12,                   // 本首共有多少个句对
  "poem": {                           // 摘句出处的基本信息
    "id": "9f2c1a7b3d40", "title": "尾犯",
    "author": "晁补之", "dynasty": "宋",
    "section": "宋词", "form": "词",
    "category": "古诗文-山水-庐山",
    "categories": ["山水/庐山"],
    "theme": "山水田园", "style": "冲淡",
    "mood": "恬淡", "scene": ["山"], "tags": { "..." }
  },
  "id": "9f2c1a7b3d40",
  "dynasty": "宋",
  "section": "宋词",
  "form": "词",
  "paragraphs": ["庐山小隐。", "..."],  // 全文
  "tags": {                          // 五维内容标签
    "theme": "山水田园", "style": "冲淡",
    "mood": "恬淡", "scene": ["山"],
    "theme_conf": 0.62,            // 题材置信度
    "theme_alt": ["咏怀抒感"]     // 次优题材
  },
  "categories": ["山水/庐山", "生活/田园"]  // 全部命中的分类
}

一首诗可以同时属于多个小类，因此 categories 是数组，category 只在其中取一个用于展示。

06精度与可信度

题材采用「规则 + 语义模型」混合判定：高置信规则保留，已验证的弱类由 DeepSeek 重判， 低置信分歧再由 v4-pro 终审。

方案top-1 准确率说明
关键词规则83.6%稳定、可解释，但弱类边界较粗
DeepSeek 单模型76.4%–76.9%语义理解较好，但常见题材不如规则稳定
混合策略87.2%规则保底 + 弱类语义重判 + 低置信终审

测法：以《唐诗三百首》《宋词三百首》的人工标签为金标准，按 UID 精确对齐 195 首， 比较 top-1 命中率。样本不大，但可复现（tools/eval_llm.py）， 排序与相对提升比绝对数值更值得参考。

theme_conf 是最终采用来源的置信度，规则与模型来源不同，数值不宜直接横向比较； 接口不提供按置信度过滤的参数，每类始终返回全部符合条件的诗词。

09判定说明

21 题材与 v1 意象分类采用两套方法，互不混淆。

分类判定方式
21 题材高置信规则 + DeepSeek 弱类重判 + 低置信 v4-pro 终审；送别/寄赠、哲理/佛道、应制与咏怀等边界均按标题事由和全篇主旨判定
v1 意象分类「意象词典 + 阈值」，规则见 tagger/categories.py
关键词权重越宽泛的词权重越低（如「风」0.5、「月」0.7），需组合达到阈值才算命中
标题加权与强制标题命中权重更高；植物 / 动物 / 食物类要求标题命中，避免正文随手取景造成误判
宋词词牌词牌只表示曲调，不作为事由标题，也不参与标题题材规则

已知局限：意象分类仍有同形歧义（如「芙蓉」兼指荷与木芙蓉）；题材分类在长诗和高度程式化文本上仍有边界误差。 若发现明显错判，可在规则表调整权重或复查对应模型的标注。
